# “原因向量”探索页面方案

## 1. 当前目标与范围

先了解已有标签、体验向量搜索，并观察哪些标签经常出现在好信号或差信号里。

在现有页面新增一个标签页，名称为 **“原因向量”**，包含两块内容：

1. 相似标签搜索：输入一段文案，按语义相似度查找已有标签。
2. 标签频次榜：分别查看好信号和差信号中经常出现的标签。

本阶段只做历史数据探索，不接入生产信号筛选，不预测新信号好坏，不生成交易建议，也不修改人工标记。本文件仅调整方案，页面和后端留待后续实现。

## 2. 功能一：相似标签搜索

### 页面交互

- 一个文本输入框和“搜索”按钮。例如输入“产品短缺，后面可能涨价”，搜索已有标签中语义接近的内容。
- 返回数量默认 20 个，可调整。
- 下方用表格展示结果，**相似度越高越靠前**。
- 表格字段：排名、标签名称、相似度、关联信号总数、好信号数、差信号数。
- 点击标签可以展开关联信号，查看股票、交易日、人工好坏标记、reason 和该标签的原文依据。
- 输入为空时不搜索；标签未建立向量索引时提示需要初始化；索引没有记录时展示空状态。

### 搜索原理

1. 将已有标签名称转成向量，即用于比较语义的一组数字。
2. 将用户输入的文案用同一个模型转成向量。
3. 计算输入与标签的余弦相似度，按分数从高到低返回结果。

**本版是一种去重后的标签名称对应一条向量，不是一条信号对应一条向量。** 同名标签只返回一行，其关联的多个信号在明细里查看。

向量仅由标签名称生成，好坏标记和出现频次不参与相似度计算，也不改变搜索排序。搜索匹配的是语义，不限于完全相同的关键词；示例中是否能搜到“供不应求”“涨价预期”，需要用实际模型验证。

相似度展示原始分数并注明“语义相似度”，不显示为上涨概率或成功率。即使排第一也可能不够相关，因此可提供最低相似度过滤，先观察实际结果再确定合适门槛。

## 3. 功能二：好／差信号标签频次榜

在同一块内容中并列展示两个榜单，或用内部切换按钮切换：

- **好信号高频标签榜**：按包含该标签的好信号数量降序排列。
- **差信号高频标签榜**：按包含该标签的差信号数量降序排列。

两榜使用相同字段：标签名称、好信号数、好信号组内出现率、差信号数、差信号组内出现率、关联信号总数、标签关联信号中的好信号占比。

点击榜单标签，同样可以查看关联信号及 reason，核对标签为什么出现。支持按标签名称筛选，并设置最少关联信号数；少量样本明确提示“样本较少”。

### 统计口径

- 好信号为人工标记 `correct`，差信号为人工标记 `fail`。
- 每个标签按不同信号 ID 计数：同一信号内重复出现同名标签只算一次；同一股票不同日期的信号分别计数。
- 好信号组内出现率 = 包含该标签的好信号数 ÷ 当前统计范围内有有效标签的好信号总数。
- 差信号组内出现率 = 包含该标签的差信号数 ÷ 当前统计范围内有有效标签的差信号总数。
- 标签关联信号中的好信号占比 = 包含该标签的好信号数 ÷ 包含该标签的全部好／差信号数。
- 分母为零时显示“暂无数据”，不显示为 0%。

好差信号总量不同，不能仅凭两边的绝对数量判断某个标签更偏向哪一组，因此同时展示组内出现率。每条信号可以有多个标签，各标签出现率相加可以超过 100%。

**高频只表示在当前人工标记样本中经常出现，不代表该标签能预测未来，也不代表它导致了好或差的结果。**

## 4. 数据来源与一致性

- 信号、reason、人工标记来自 SQLite 的 `trend_mark`。
- 标签和原文依据来自 `trend_mark_tagging`，按信号 ID 关联。
- 仅纳入与当前信号代码、交易日及 reason 快照一致的有效标签；未打标签、打标失败或原文已变化的记录暂不参与统计。
- 页面顶部展示：当前信号总数、有有效标签的好／差信号数、未纳入数量、去重标签数、索引更新时间，避免把尚未完成的标签统计当作全部样本结果。
- 同名标签去重时先统一首尾空格和全角／半角等基本格式；不同表述暂不自动合并，例如“涨价预期”和“产品已涨价”分别保留。
- 搜索可找出近义标签，但榜单初版仍按标签名称分别计数，不凭相似度自动合并。后续有需要再增加人工同义标签归并。

## 5. 技术实现思路

- 沿用现有前端和后端结构，新增“原因向量”入口、搜索区域、榜单区域及信号明细。
- 向量搜索先用本地环境验证：可采用 BGE-M3 文本向量模型与 Qdrant 本地持久化模式，暂不部署生产向量服务。
- 标签名称使用稳定 ID 建立索引，记录模型版本；输入文案必须使用相同模型。更换模型后重建整个标签索引。
- SQLite 保留标签与信号的关联关系，负责榜单计数及明细查询；**频次榜不依赖向量数据库**。
- 初版提供手动“刷新标签索引”：补充新标签、移除已无有效信号关联的标签。好坏标记变化只影响统计，不需要重新生成文本向量。
- 搜索结果的关联数量与榜单使用同一有效数据范围；索引尚未同步时提示状态，并过滤已经失效的标签。

### 国内网络下的安装与模型下载

当前环境为国内网络，后续安装依赖和下载模型时，**优先使用可信的国内镜像或国内模型平台**，避免默认依赖海外站点。Python 包镜像和模型下载源是两套配置，需要分别处理。

- **Python 依赖**：优先使用清华 PyPI 镜像 `https://pypi.tuna.tsinghua.edu.cn/simple`，安装时通过 `python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple <包名>` 指定；优先使用单次命令参数，不擅自修改全局 pip 配置。
- **嵌入模型**：初版选用 `BAAI/bge-m3`，使用其 1024 维稠密向量。优先从 ModelScope（魔搭）等国内模型平台下载对应模型，实施时核对发布方、模型版本和文件完整性，不能把名称相近的其他模型当作同一模型。
- **Hugging Face 下载备选**：若采用 Hugging Face 下载工具，可尝试第三方镜像 `https://hf-mirror.com`。Windows PowerShell 中先设置 `$env:HF_ENDPOINT = "https://hf-mirror.com"`，再启动下载程序；该配置仅影响支持此变量的工具，不会改变 pip 下载源。镜像的可用性与同步状态需当时验证，不保证长期可用。
- **本地加载**：模型完整下载后固定存放在本地目录，历史标签向量生成和搜索服务均从该目录加载，避免每次启动或搜索重新联网下载；同时记录模型版本。
- **PyTorch**：根据实际 Python 版本、CPU/GPU 和 CUDA 环境选择兼容安装包。普通 PyPI 镜像不一定包含需要的 GPU 构建，不能仅替换镜像地址就认定 GPU 可用；初版可以先用 CPU 验证功能。
- **安全与回退**：使用 HTTPS，不关闭证书校验。镜像不可用时明确报错或切换已核实的下载源，不静默更换模型；私有访问令牌不要发送给未经信任的第三方镜像。

以上是后续实施要求，本阶段仅记录方案，不执行安装、模型下载或环境配置修改。

## 6. 实施顺序与验收

1. 先实现标签统计与两个榜单，核对数量，并能查看对应信号原文。
2. 再建立标签向量索引，实现输入文案搜索和相似度排序。
3. 将两块内容接入“原因向量”标签页，补齐空状态、刷新状态和错误提示。

验收重点：同名标签不重复展示，同一信号不重复计数，好坏数量能追溯到原始记录；搜索结果按相似度降序排列；未标注或已失效数据不混入榜单；全程不改变现有 reason、标签内容与人工好坏标记。
